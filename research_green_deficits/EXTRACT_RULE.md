# How to unpack the repository without destroying your own results

**One rule: extract the CODE, never `output/`.**

## The failure this prevents

`output/` is tracked in git — 205 files, including every `.mat`. The copies in
the repository are old: `wealth_fit_results.mat` and `convenience_kvj.mat` were
last committed at PR #155 and predate the variables later runs add to them
(`IDENT`, `kvj_logel`).

So unpacking the archive over the working folder **overwrites freshly computed
results with stale committed ones**. It happened at least three times during
the R11.29–R11.38 sequence, and each time the symptom looked like something
else:

1. `wealth_concentration_fit` was run and produced the `IDENT` diagnostic;
   the ledger reported V1 as measured — 9 configs, 3 ties, top-10 spread
   0.0137.
2. The project was re-extracted to pick up new drivers.
3. The extract restored the PR #155 `wealth_fit_results.mat`, which has no
   `IDENT`.
4. The next ledger run reported V1 as `NOT YET MEASURED` again, and the
   re-run instruction was issued a second time — for work that had already
   been done and then silently reverted.

The same loop ran for `convenience_kvj.mat` and `kvj_logel`, which is why the
demand-curve log-elasticity keeps falling back from a graded row to `PENDING`.

The ledger's own STALE detector (R11.29) catches the *state* correctly every
time. What it cannot see is the *cause*, because from inside MATLAB a clobbered
file and a never-generated file are identical.

## The rule

When unpacking, exclude:

```
research_green_deficits/output/          <- every result you computed
research_green_deficits/paper/numbers_auto.tex   <- generated by export_paper_numbers
```

Everything else — `*.m`, `src_project/`, `src/`, `paper/*.tex` except
`numbers_auto.tex`, `CODE_VERSION.txt`, the `.md` documents — should be
refreshed on every extract.

The direction of travel is one-way per file type, and that is the whole
principle:

| file type | flows | never flows |
|---|---|---|
| code (`*.m`), docs, manuscript source | repo → your machine | |
| results (`output/**`), `numbers_auto.tex` | your machine → repo | repo → your machine |

If your unpacker cannot exclude a folder, unpack to a **scratch directory**
and copy only the code across. Do not unpack over a folder holding results you
have not yet pushed.

## Two things this does not fix

**`CODE_VERSION.txt` going missing.** Separate problem, same unpacker. As of
R11.39 the banner distinguishes *absent* (one quiet note; the revision constant
inside `kv_code_version.m` is authoritative and sufficient) from *present but
disagreeing* (a real mixed extract, worth shouting about). An absent file is
not an error — but it does mean the extract is dropping files, which is worth
knowing before it drops one that matters.

**Whether `output/*.mat` should be tracked at all.** Arguably not: they are
binary, so they cannot be read or reviewed in a diff, and their only function
in the repository is to be shipped back and overwrite the good copies. The
`.txt` tables and `.png` figures under `output/` are different — those are
readable, reviewable deliverables and should stay tracked. Untracking roughly
a hundred `.mat` files is a repository decision with one real cost: a fresh
clone would have to re-solve anything a driver currently seeds from a shipped
`.mat` (for example the `q_seed` warm start in `main_twoasset_ownership_kv`).
Every such site is guarded by `exist(...)` and would still run, only slower.
Left for the author to decide; the extract rule above makes it safe either way.
