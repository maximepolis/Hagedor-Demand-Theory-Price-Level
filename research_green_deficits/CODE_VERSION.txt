# R11.20 main_credibility_reversal's first run returned NOTHING USABLE: 9 of
#        12 cells fell under the solver's clearing residual and the
#        front-loading grid printed as all dots. The cause was the sweep
#        design, not the solver. With rbar = 1.96% the map h -> s =
#        rbar/(rbar+h) is violently convex: h = 0.05, an expected program life
#        of 20 years and a mild assumption in words, removes 72% of the
#        program's PV, so the price response scales down with it and vanishes.
#        The sweep is now posed in the PV WEIGHT s (default [1 .9 .8 .7]) with
#        the implied hazard reported beside it; HGRID_EXPLICIT = true restores
#        raw-hazard sweeping. This is itself the answer to the referee's "at
#        least two reversal hazards": at a 2% real rate there is no graded
#        middle ground in h -- holding s >= 0.9 needs an expected life of 459
#        years, i.e. indistinguishable from perfect credibility, while
#        anything a reader would call real reversal risk already halves the
#        program.
# R11.19 the run was on course to DISCARD its own answer. Gate 11 proper is
#        computed only over CERTIFIED cells and no cell certifies, so a full
#        matrix would have reported "not computable" while holding nine
#        perfectly good dP values. contrast_gates now also reports a
#        PROVISIONAL block over every cell that produced a finite dP, split
#        into the two questions that are genuinely different: MAGNITUDE
#        (spread in dP relative to dP -- what Gate 11 asks) and ORDERING
#        (does dP keep its sign across every discretization). The ordering is
#        the weaker and more robust claim because it compares two solves on
#        the SAME grid, where common discretization error differences out.
#        Every line is labelled provisional and uncertified.
#        Also: gate 6 was failing the BEST case. Churn compares the adjuster
#        index arrays across the last two VFI sweeps, so a warm start already
#        at the fixed point converges on sweep 1 with nothing to compare
#        against, reports NaN, and is failed as unmeasured. Now scored
#        not-applicable -- but only when the VFI reached the HARD tolerance
#        and did not soft-accept, so a solve that gave up cannot reach the
#        exemption. vfi_iters is propagated for this.

#        struct( ... ) call. MATLAB cannot parse a comment-only line within a
#        `...` continuation -- the error is "Invalid expression" pointing at a
#        column in the middle of the construct, which reads like a delimiter
#        problem. Comment moved above the statement, and
#        paper/check_matlab_blocks.py now checks for this class with six new
#        controls (a trailing comment after `...` is fine; a comment inside

# R11.17 the widened FAST matrix runs for hours per cell, so the run is now
#        SURVIVABLE: after every cell (failed ones included -- a failure is a
#        result) the partial CELL array is checkpointed to
#        output/quarantine/cert_<TRACK>_checkpoint.mat, written to a .tmp and
